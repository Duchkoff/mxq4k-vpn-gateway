# MXQ 4K → Linux VPN-шлюз. Полная инструкция по перепрошивке

**Приставка:** MXQ 4K, плата **XT-MX4N-V03** (2017/02/08), SoC **Rockchip RK3229**, NAND 8 ГБ Micron (сырой, без FTL-заголовка), Wi-Fi **SSV6051P** (модуль ядра `ssv6x5x`).

**Результат:** Armbian в NAND, веб-панель управления VPN (xray + подписки Happ/LaliVpn) на порту 8080, прозрачный VPN-шлюз для устройств локальной сети.

Файлы к инструкции — в папке `файлы/` рядом с этим файлом.

---

## 1. Важные особенности железа (выяснено опытным путём)

- **Прямая запись образа в NAND через maskrom НЕ работает.** Bootrom не принимает чужой idbloader, NAND требует заводской FTL-заголовок. Писать первые 4 МБ NAND нельзя вообще.
- Рабочий путь — загрузка с **SD-карты** (bootrom умеет грузить SD сразу, без прошивки).
- В NAND приставки заводской idbloader на 0–4 МБ оставлен нетронутым — он же потом грузит систему.
- Wi-Fi SSV6051P поднимается модулем `ssv6x5x` (после `modprobe ssv6x5x` появляется wlan0).
- Кнопка reset на плате + подключение OTG-USB к ПК = maskrom (VID:PID `2207:320b`, `rkdeveloptool`).

## 2. Загрузка Multitool с SD

1. SD-карта от 4 ГБ (здоровая! одна 14-гиговая карта «умирала» при записи и глючила).
2. Распаковать и записать:
   ```bash
   xz -dc multitool.img.xz | sudo dd of=/dev/sdX bs=4M status=progress
   ```
3. Вставить SD в приставку, подать питание — грузится Multitool (автоматом с SD, кнопку жать не нужно).
4. Multitool поднимает SSH: `root@<IP>` (IP смотреть в панели роутера), **пароль пустой**.

## 3. Установка Armbian в NAND (ручная steP-nand)

В Multitool по SSH (образ Armbian предварительно положить в `/images/` на SD или доступное место):

```bash
# rootfs со смещения 0x8000 (первые 4 МБ не трогаем!)
xz -dc /images/Armbian_22.02.0-trunk_Rk322x-box_bullseye_legacy_4.4.194_minimal.img.xz | \
  dd of=/dev/rknand0 bs=512K skip=8 seek=32
# u-boot + trust поверх (они же внутри образа, дублируем как делает скрипт multitool)
dd if=/mnt/bsp/legacy-uboot.img of=/dev/rknand0 bs=4M seek=1
dd if=/mnt/bsp/trustos.img of=/dev/rknand0 bs=4M seek=2
# чистим таблицу разделов и создаём корень
dd if=/dev/zero of=/dev/rknand0 bs=64K seek=0 count=8 conv=notrunc
/sbin/sgdisk -o /dev/rknand0
/sbin/sgdisk --zap-all -n 0:32768:+4G /dev/rknand0
```

Вынуть SD, перезагрузить — грузится Armbian с NAND.

## 4. Первоначальная настройка Armbian

- SSH: `root@<IP>`, пароль по умолчанию `1234` → сразу сменить (`echo 'root:ПАРОЛЬ' | chpasswd`).
- Сеть — NetworkManager (`nmcli`). Для строго-кабельного режима: Wi-Fi подключение удалить/отключить.
- LED не мигать: `echo none > /sys/class/leds/working/trigger; echo 1 > /sys/class/leds/working/brightness` + systemd-юнит (Type=oneshot, WantedBy=multi-user.target).
- Модули в автозагрузку: `echo ssv6x5x >> /etc/modules` (если Wi-Fi нужен).

## 5. Xray + веб-панель (файлы `status-web.py`, `Xray-linux-arm32-v7a.zip`)

1. `python3 -c "import zipfile; zipfile.ZipFile('Xray-linux-arm32-v7a.zip').extractall('/opt/xray')"` (unzip в minimal-образе нет; внимание — нужен именно **arm32-v7a**, бинарник `linux-32` — это i386!).
2. `status-web.py` → `/usr/local/bin/status-web.py`, systemd-юнит `status-web.service` (python3, порт 8080, ThreadingTCPServer + allow_reuse_address).
3. Панель: список серверов `/usr/local/etc/xray/servers.json`, подписки `subs.json`, активный `active`, HWID `hwid`.
4. **Баг, на который потрачено больше всего времени:** `xray run -test -c file.new` падает — xray не понимает расширение `.new`, писать временный конфиг как `*.tmp.json`.

## 6. Подписки Happ/LaliVpn (Remnawave) — ключевые находки

- Панель **Remnawave**: лендинг на URL подписки, реальный конфиг отдаётся только с заголовком **`x-hwid: <uuid>`** + `User-Agent: Happ/1.0`.
- HWID фиксируется один раз в `/usr/local/etc/xray/hwid`. **Новый случайный HWID панель блокирует** (лимит устройств) и отдаёт заглушку `vless://00000000-...@0.0.0.0:1` «Обновите приложение». Освобождать слот — в приложении/боте провайдера.
- Ответ — **JSON-массив конфигов xray-формата**, каждый элемент = один сервер с полем `remarks` (красивое имя «🇩🇪 Германия ⚡»). Внутри `outbounds` — цепочка fallback (vless + hysteria2 + direct).
- Брать **первый vless outbound** из каждого конфига, имя — из `realitySettings` чистить от `fingerprint`. **Hysteria2-only сервера пропускаются** (xray не умеет; для них нужен sing-box).

## 7. Прозрачный VPN-шлюз (файл `gw-rules.sh` + `gw-rules.service`)

- xray слушает dokodemo-door `:12345` (followRedirect, sniffing) в дополнение к SOCKS5 `:10808` / HTTP `:10809`.
- iptables (на ядре 4.4 нужен **iptables-legacy**: `update-alternatives --set iptables /usr/sbin/iptables-legacy`, nf_tables нет):
  - `PREROUTING`: трафик LAN→LAN вернуть, остальной TCP → REDIRECT 12345, UDP/53 → REDIRECT 12345 (DNS через туннель);
  - `POSTROUTING`: MASQUERADE (симметричный обратный путь через приставку);
  - `net.ipv4.ip_forward=1`.
- **DNS на приставке: dnsmasq + stubby (DNS-over-TLS).** КРИТИЧНО: провайдер ДУШИТ/перехватывает UDP 53 — запросы к 8.8.8.8 и даже к 1.1.1.1 периодически таймаутятся (симптом: «подключено, нет интернета», DNS-ошибки). Решение: stubby слушает 127.0.0.1:8053 (DoT → 1.1.1.1:853, `tls_auth_name: cloudflare-dns.com`), dnsmasq (`/etc/dnsmasq.d/gateway.conf`) форвардит на `127.0.0.1#8053`, кэш 1000. Конфиг stubby: `/etc/stubby/stubby.yml`. Устройствам DNS = IP приставки.
- **Критичный баг (потрачено много нервов):** `systemctl enable --now xray` НЕ перезапускает запущенный xray — панель писала новый конфиг, а процесс гонял старый (VPN «не выключался», ходил со старым сервером). Правильно: `systemctl enable xray && systemctl restart xray`.
- **«Отключить VPN» ≠ остановить xray.** Выключается переключением outbound на `{"protocol":"freedom"}` (прямой доступ) — порт 12345 продолжает слушать, устройства со шлюзом .59 не теряют интернет. Кнопка «Включить VPN» возвращает последний выбранный сервер. Состояние: `active=-1` в файле `/usr/local/etc/xray/active` = прямой режим.
- Использование на устройстве: статический IP `192.168.3.x`, шлюз = IP приставки, DNS = IP приставки (dnsmasq) или 1.1.1.1. Устройства без этой настройки ходят напрямую (режим «некоторые устройства через VPN»).
- **Режимы подключения (xray routing, кнопки у каждого сервера):**
  - **Обход (bypass, по умолчанию):** основной трафик — НАПРЯМУЮ (полная скорость, Яндекс.Музыка/банки работают), через VPN — заблокированное/замедленное: базовые категории (geosite: youtube, google, facebook, instagram, twitter, discord, openai, github, spotify + домены googlevideo/ytimg/ggpht/googleusercontent) + **автообновляемые списки** (~83 000 доменов, файл `/usr/local/etc/xray/blocked-extra.txt`): [no-russia-hosts](https://github.com/dartraiden/no-russia-hosts) (сервисы, сами ушедшие/режущие РФ) + [Re-filter-lists](https://github.com/1andrevich/Re-filter-lists) `domains_all.lst` (реестр РКН). Плюс статичные «ушедшие из РФ»: soundcloud, netflix, crunchyroll, hbo/max, disneyplus, dazn, twitch. Обновление — в `sub-update.py` (раз в час вместе с подписками).
  - **Весь трафик (full):** всё через VPN, кроме RU-геоблоков (yandex, vk, ok, mailru, avito, ozon, wildberries, kinopoisk, sberbank, tinkoff, gosuslugi — ВСЕГДА напрямую, иначе Яндекс.Музыка отказывает по гео).
  - **Gemini/AI** — автоматически через отдельный сервер с «GEMINI» в имени (если есть в пуле), в обоих режимах.
  - ВАЖНО: не все коды geosite есть в dat-файле (нет: tinkoff, gosuslugi, googlevideo, ytimg, gemini) — такие домены перечислены вручную через domain:. Проверка: `xray run -test` на конфиге с одной категорией.
- **QUIC:** FORWARD REJECT udp/443 от LAN — клиенты принудительно падают на TCP, иначе YouTube висит (QUIC уходит мимо туннеля российским IP). Файл: `gw-rules.sh`.
- Автообновление подписок: `sub-update.timer` (OnBootSec=3min, OnUnitActiveSec=1h) → `sub-update.py` (обновляет подписки из subs.json и список заблокированных доменов).
- **Архив Debian bullseye переехал:** в `/etc/apt/sources.list` заменить `deb.debian.org`/`security.debian.org` на `archive.debian.org`, строку bullseye-backports удалить, иначе apt 404.
- Тесты curl должны идти с `--socks5-hostname` (домен уходит в прокси, иначе правила по доменам не срабатывают).
- Роутер (Huawei AX2) не настраивается: DHCP-шлюз он не отдаёт, поэтому шлюз прописывается вручную на каждом устройстве. В панели AX2 есть только «Список привязок» — закрепить 192.168.3.59 за MAC приставки.
- Проверка шлюза с любого Linux-хоста в сети: `sudo ip route add <IP назначения>/32 via 192.168.3.59` → сделать запрос → `sudo ip route del ...`. IP-check: api.ipify.org (прямой = 91.109.143.190, VPN = 135.125.189.173 и т.п.).
- LG webOS ТВ: если у ТВ активны и Wi-Fi и кабель — он выбирает интерфейс сам, шлюз прописывать на том, что реально используется (лучше Wi-Fi выключить). Настройка по SSH возможна с root (Homebrew Channel: ssh root@<IP>, пароль зависит от метода рута).

## 8. Текущее состояние приставки

- IP: `192.168.3.59` (DHCP, закрепить в роутере по MAC `CA:58:70:3D:C4:96`), hostname `rk322x-box`, root-пароль у владельца.
- Сервисы: `status-web` (8080), `xray`, `gw-rules`, `dnsmasq`, `stubby` (DoT), `led-static`.
- Подписка LaliVpn загружена, 21 сервер (vless), веб-управление: подписки, удаление, пинг (TCP 12 потоков), вкл/выкл VPN.

## 9. Тест-клиент на ESP32-C3 (для проверки шлюза без телефона)

- Плата ESP32-C3 Super Mini, USB → `/dev/ttyACM0`. Доступ: `sudo chmod 666 /dev/ttyACM0`.
- Прошивка была мусорная (отвечала `ESP-OK` на всё) — перепрошит MicroPython: `ESP32_GENERIC_C3-latest.bin` через esptool (`pip install esptool mpremote` в venv) на `0x0`.
- Управление: `mpremote connect /dev/ttyACM0 exec "<python>"`.
- Скрипт теста (подключение к Wi-Fi zahar + HEAD-запросы через шлюз):
  ```python
  import network, socket, ssl, time
  w=network.WLAN(network.STA_IF); w.active(True); w.connect('<SSID>','<WIFI_PASSWORD>')
  # дождаться isconnected(), затем:
  w.ifconfig(('192.168.3.61','255.255.255.0','192.168.3.59','192.168.3.59'))
  # далее getaddrinfo + socket + ssl.wrap_socket + HEAD-запрос
  ```
  ВАЖНО: у C3 всего ~170 КБ RAM — большие ответы дают MemoryError, тестировать HEAD-запросами, не GET.
- Полезный эффект: конфиг xray с правилом на 83k доменов (~3 МБ) влезает и работает на RK3229.
