# Установка с нуля: ТВ-приставка → VPN-шлюз

Руководство для любого, кто хочет повторить: превратить ТВ-приставку на Rockchip RK3229/RK3228A (например, MXQ 4K, плата XT-MX4N-V03) в прозрачный VPN-шлюз. Проверено на MXQ 4K с NAND-памятью.

Что получится в итоге: приставка стоит рядом с роутером, включена по кабелю, а любое устройство в сети (телефон, ТВ, компьютер) может пустить свой трафик через VPN, просто указав шлюзом IP приставки. Российские сервисы (Яндекс.Музыка, банки, маркетплейсы) идут напрямую с полной скоростью, заблокированные — через VPN.

---

## Шаг 0. Что понадобится

- ТВ-приставка на RK3229/RK3228A (MXQ 4K и аналоги).
- microSD-карта от 4 ГБ (исправная — глючная карта = глюки при записи).
- Кабель USB–USB (или USB–Type-C по OTG) для подключения приставки к компьютеру.
- Роутер с DHCP, компьютер с Linux (можно live-USB).
- Подписка на VPN, выдающая конфиги xray/vless (подойдёт любая панель типа Remnawave/3x-ui/Happ).

## Шаг 1. Загрузка Multitool с SD-карты

Bootrom чипов Rockchip умеет грузиться с SD-карты без всякой прошивки — это наш вход.

```bash
# скачать образ: https://forum.armbian.com/topic/16926-testers-wanted-mxq-rk322x-tv-box-images/
xz -dc multitool.img.xz | sudo dd of=/dev/sdX bs=4M status=progress   # sdX = твоя карта, без цифры!
```

Вставить карту в приставку, подать питание. Multitool загрузится сам и поднимет SSH (смотри IP в панели роутера, логин `root`, пароль пустой).

> **Важно (особенность NAND на этих приставках):** прямая запись образа в NAND через maskrom НЕ работает — NAND требует заводской FTL-заголовок, чужой idbloader bootrom не примет. Поэтому ставим систему в NAND «в обход»: грузимся с SD и копируем rootfs поверх заводского загрузчика, не трогая первые 4 МБ.

## Шаг 2. Установка Armbian в NAND

В Multitool по SSH (образ Armbian положить в `/images/` на SD или на сетевую шару):

```bash
# rootfs со смещения 0x8000 (первые 4 МБ NAND не трогаем!)
xz -dc /images/Armbian_22.02.0-trunk_Rk322x-box_bullseye_legacy_4.4.194_minimal.img.xz | \
  dd of=/dev/rknand0 bs=512K skip=8 seek=32
# u-boot + trust
dd if=/mnt/bsp/legacy-uboot.img of=/dev/rknand0 bs=4M seek=1
dd if=/mnt/bsp/trustos.img of=/dev/rknand0 bs=4M seek=2
# чистим таблицу разделов и создаём корень
dd if=/dev/zero of=/dev/rknand0 bs=64K seek=0 count=8 conv=notrunc
/sbin/sgdisk -o /dev/rknand0
/sbin/sgdisk --zap-all -n 0:32768:+4G /dev/rknand0
```

Вынуть SD, перезагрузить — грузится Armbian с NAND.

## Шаг 3. Первичная настройка Armbian

```bash
# зайти по SSH (root, пароль по умолчанию 1234) и сразу сменить пароль
echo 'root:ВАШ_ПАРОЛЬ' | chpasswd
# сеть — строго по кабелю (Wi-Fi-модуль SSV6051P на этих платах не заводится драйвером)
nmcli con mod "Проводное соединение" connection.autoconnect yes
# LED не мигать
echo none > /sys/class/leds/working/trigger; echo 1 > /sys/class/leds/working/brightness
```

## Шаг 4. Xray + веб-панель

```bash
# xray (нужен arm32-v7a! linux-32 = i386, не подойдёт)
mkdir -p /opt/xray
python3 -c "import zipfile; zipfile.ZipFile('Xray-linux-arm32-v7a.zip').extractall('/opt/xray')"

# панель
cp files/status-web.py /usr/local/bin/status-web.py
cat > /etc/systemd/system/status-web.service <<'EOF'
[Unit]
Description=MXQ gateway panel
After=network.target
[Service]
ExecStart=/usr/bin/python3 /usr/local/bin/status-web.py
Restart=always
[Install]
WantedBy=multi-user.target
EOF
systemctl enable --now status-web
```

Открыть `http://IP-ПРИСТАВКИ:8080`. Вставить подписку (URL) или vless-ссылку. Панель сама скачает серверы, проверит конфиг (`xray run -test`) и подключится.

Поддерживаются:
- подписки Happ/Remnawave (JSON; если паналь требует HWID — файл `/usr/local/etc/xray/hwid` создаётся автоматически, **не удаляйте его**: повторная регистрация HWID может упираться в лимит устройств у провайдера);
- обычные `vless://`-ссылки;
- **hysteria2**-серверы: панель поднимает sing-box-сайдкар автоматически (нужен бинарник sing-box 1.11.x в `/opt/sing-box`, см. systemd-юнит в NOTES).

## Шаг 5. DNS, который не душит провайдер

Многие провайдеры режут/перехватывают UDP 53 — из-за этого «Wi-Fi подключён, интернета нет». Решение — DNS-over-TLS:

```bash
apt-get install -y dnsmasq stubby   # Debian bullseye: репозитории переехали на archive.debian.org
cp files/stubby.yml /etc/stubby/stubby.yml          # DoT -> 1.1.1.1:853
cp files/gateway.conf /etc/dnsmasq.d/gateway.conf   # dnsmasq -> stubby, кэш
systemctl enable --now stubby dnsmasq
```

## Шаг 6. Прозрачный шлюз

```bash
cp files/gw-rules.sh /usr/local/bin/gw-rules.sh
chmod +x /usr/local/bin/gw-rules.sh
cat > /etc/systemd/system/gw-rules.service <<'EOF'
[Unit]
Description=gateway iptables rules
After=network.target
[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/usr/local/bin/gw-rules.sh
[Install]
WantedBy=multi-user.target
EOF
# ядро 4.4: нужен iptables-legacy (nf_tables нет)
update-alternatives --set iptables /usr/sbin/iptables-legacy
systemctl enable --now gw-rules
```

Что делает скрипт: разрешает форвардинг, заворачивает весь TCP от клиентов LAN в xray (dokodemo-door :12345), DNS (UDP 53) — в локальный dnsmasq, блокирует QUIC (UDP 443) — иначе YouTube висит, поднимая замедлённые QUIC-потоки, и делает MASQUERADE.

## Шаг 7. Подключение устройств

На устройстве, которое должно ходить через VPN, задать статику:

| Параметр | Значение |
|---|---|
| IP | свободный адрес из подсети роутера (напр. 192.168.1.50) |
| Маска | 255.255.255.0 |
| Шлюз | **IP приставки** |
| DNS | IP приставки (или любой — DNS всё равно перехватывается) |

- **Android**: Настройки → Wi-Fi → сеть → Дополнительно → IP «Статический». Обязательно выключи **«Частный DNS»** (он ходит на 8.8.8.8 мимо шлюза и ломает маршрутизацию по доменам).
- **Windows**: Параметры адаптера → IPv4 → вручную.
- **ТВ (webOS)**: настройки сети, статический IP, шлюз = приставка.

Проверка: на устройстве открыть `2ip.ru` — страна должна смениться на страну VPN-сервера.

Чтобы вернуть обычный интернет — вернуть DHCP на устройстве.

## Шаг 8. Автообновление подписок

```bash
cp files/sub-update.py /usr/local/bin/sub-update.py
cat > /etc/systemd/system/sub-update.timer <<'EOF'
[Unit]
Description=refresh subscriptions hourly
[Timer]
OnBootSec=3min
OnUnitActiveSec=1h
Unit=sub-update.service
[Install]
WantedBy=timers.target
EOF
cat > /etc/systemd/system/sub-update.service <<'EOF'
[Unit]
Description=refresh subscriptions
[Service]
Type=oneshot
ExecStart=/usr/bin/python3 /usr/local/bin/sub-update.py
EOF
systemctl enable --now sub-update.timer
```

## Режимы и категории

- **«Весь трафик»** — всё через VPN, кроме RU-сервисов и RU-IP (Яндекс.Музыка/банки работают, нет геоблоков). Рекомендуется для телефонов.
- **«Обход»** — напрямую всё, кроме заблокированного: YouTube, Instagram, Discord, Telegram, WhatsApp, SoundCloud + автообновляемые списки (реестр РКН ~83 000 доменов + сервисы, ушедшие из РФ).
- **Категории с отдельным сервером**: Gemini/AI (включая Antigravity), Игры (Roblox, Supercell, Garena, HoYoverse), YouTube — выбираешь сервер с лучшим пингом, трафик категории пойдёт через него независимо от основного.

## Траблшутинг

| Симптом | Причина / решение |
|---|---|
| «Подключено, нет интернета» на Android | Включён «Частный DNS» → выключить; либо провайдер душит UDP 53 → шаг 5 |
| YouTube грузится, но видео не играет | QUIC: убедись, что gw-rules применён (REJECT udp/443) |
| Игра не коннектится через шлюз | игра ходит на голый IP без домена — пиши в issues, добавим IP-сети |
| Сменил сервер, а трафик идёт через старый | `systemctl enable --now` НЕ перезапускает xray; панель делает restart сам, при ручной правке конфига используй `systemctl restart xray` |
| В панели заглушка vless://00000000-...@0.0.0.0 | провайдер заблокировал новый HWID (лимит устройств) — освобождай слот у провайдера, файл hwid не удалять |
